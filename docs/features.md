# Feature index

What the factory implements, with a status for each feature that is backed by the code on
`main`. Use it to see what exists, what is partly wired, and what is only designed.

Related docs: [`run-lifecycle.md`](run-lifecycle.md) (what one run does, step by step),
[`scheduler.md`](scheduler.md) (the poll loop and its dispatch rules),
[`configuration.md`](configuration.md) (every knob and where it is read).

## How to read this

Every status below was decided from call sites, not from specs. The evidence is cited as
`path:line` or `path` + symbol. This file was first written against commit `254c9d2`; its
line numbers were re-checked against `64cd44a`, after
[PR #519](https://github.com/omniscient/dark-factory/pull/519) (per-scenario budget files),
[PR #524](https://github.com/omniscient/dark-factory/pull/524) (autopilot adapter lookup) and
[PR #525](https://github.com/omniscient/dark-factory/pull/525) (comments and board read through the provider CLI). They will
drift again; the symbol names are the stable reference.

| Status | Meaning |
|---|---|
| **Live** | Called from `scheduler.sh`, `entrypoint.sh`, a workflow node or a phase command, and on by default. Also used for operator entry points that a person runs by design (marked "operator-run"). |
| **Partial** | Some paths are wired. The row says which are not. |
| **Measured only** | Runs and records a result, but the result gates nothing and changes no prompt. |
| **Dormant** | The code exists and has tests, but nothing calls it, or it is wired and disabled by default. The row says which. |
| **Experimental** | A spike or seam proof, kept for reference. Not on any run path. |
| **Designed only** | A reserved name, config key or ticket with no implementation behind it. |

Three things to keep in mind:

- "On by default" means the value in [`config/config.yaml`](../config/config.yaml) or the
  code default. A target's `.archon/.env` or `deploy/instance.env` can override most flags,
  and those files are not in this repo. The two committed instance files under
  `deploy/instances/` set none of `EPIC_AUTOPILOT_ENABLED`, `MAIN_RED_AUTOFIX_ENABLED` or
  `FACTORY_MODEL_PROXY_ENABLED`.
- "Tests" means `python -m pytest tests/` (every `tests/test_*.py` runs in CI) unless a
  shell test is named. Only 27 of the 50 `tests/test_*.sh` scripts are listed in
  [`.github/workflows/ci.yml`](../.github/workflows/ci.yml); the rest run only by hand.
- Ticket links are to `omniscient/dark-factory`. Their state was checked on 2026-11-16 and
  updated for [#511](https://github.com/omniscient/dark-factory/issues/511) (now closed) after `64cd44a`.

## Run pipeline

One dispatched container runs [`entrypoint.sh`](../entrypoint.sh), which either handles the
intent inline (`recheck`, `deconflict`, `fix-main`) or runs the workflow
[`workflows/archon-dark-factory.yaml`](../workflows/archon-dark-factory.yaml). See
[`run-lifecycle.md`](run-lifecycle.md).

## Not wired / candidates for removal

Code that exists on `main` and that nothing in the scheduler, entrypoint, workflow or phase
commands calls. "Keep" or "remove" is a product decision; this list only records the fact.
This list, with the unreachable workflow paths and the shell tests missing from CI, is
tracked in [#531](https://github.com/omniscient/dark-factory/issues/531). Related open
tickets for the other documents' oddity lists:
[#526](https://github.com/omniscient/dark-factory/issues/526) (failed-run bookkeeping),
[#527](https://github.com/omniscient/dark-factory/issues/527) (DAG gate enforcement),
[#528](https://github.com/omniscient/dark-factory/issues/528) (config keys that never reach
their reader, including the unread keys listed below),
[#529](https://github.com/omniscient/dark-factory/issues/529) (loose scheduler matching),
[#530](https://github.com/omniscient/dark-factory/issues/530) (state transitions) and
[#532](https://github.com/omniscient/dark-factory/issues/532) (MarketHawk-specific steps).

Nothing calls it:

- `scripts/check_preview_creds.sh`: no caller, no test, no CI step.
- `scripts/context_pack.py`: only `evals/token_opt_eval.py` imports it. The refine and plan
  commands carry a branch for a pack that no node produces.
- `scripts/memory_maintain.py`: tested, never invoked.
- `scripts/memory_import.py` and the index path of `scripts/memory_retrieve.py`: the index
  is never built by the factory, so every run takes the markdown-scan path.
- `scripts/factory_core/handoff.py`: CLI with tests, no caller.
- `scripts/factory_core/verifier.py` `run`: no caller. `scripts/cost_report_marker_check.py`
  exists only as an example verifier for it.
- `scripts/factory_core/mechanism_candidate.py` and `scripts/state_governance_audit.py`:
  fixture validators with no caller (the first belongs to open epic
  [#463](https://github.com/omniscient/dark-factory/issues/463)).
- `scripts/factory_core/breaker.py` `_evaluate_loop_caps` / `_advance_loop_counters` /
  `add_loop_tokens`: reachable only with a `loop_entry`, which no caller passes.
- `scripts/reconcile_cost_reports.py` and `run_record.py`'s `issue-economics` /
  `backfill-economics` subcommands: manual, read-only tools.
- `commands/ceiling-revisit.md`, `scripts/ceiling_revisit.py`, `scripts/fetch_scorecard.py`:
  manual only. `fetch_scorecard.py` is also imported by `evals/skill_flow_eval.py`.
- Workflow nodes `setup-branch-resolve`, `preview-up-resolve`, `push-resolve`: on a path
  (`resolve`) that no scheduler dispatch reaches.
- `scripts/factory_core/providers/codehost/gitlab.py`: not registered.
- The spikes: `scripts/eval_mem0.sh`, `scripts/mem0_*.py`,
  `scripts/requirements-mem0-spike.txt`, `scripts/eval_agentmemory.sh`,
  `scripts/iii-config.agentmemory.yaml`.

Wired and off by default (not removal candidates; listed so the "Dormant" rows are in one
place): main-red autofix, epic autopilot, model proxy.

Config keys that nothing reads: `refine.skip_labels`, `refine.min_issue_body_length`,
`plan.skip_labels`, `token_optimization.escalation.opus_only_for`, and the adapter key
`safety.dispatch_ceiling_keywords` when set by a target.

## Not determined

- `archon-config.yaml` at the repo root: no reference in the scheduler, entrypoint,
  workflow, `Dockerfile`, tests or docs (grep). Whether Archon reads it by convention from
  a checkout was not checked.
- Preview behaviour on a target that is not shaped like MarketHawk: the classifier and the
  fail-soft path (`preview_fail`, `workflow:893`) exist, but what `preview-up` does with a
  target that has no `backend/` or `frontend/` was not traced.
- Whether the live instances turn on epic autopilot, main-red autofix or the model proxy:
  those flags would be in each target's `.archon/.env` or the host's `deploy/instance.env`,
  which are not in this repo.
